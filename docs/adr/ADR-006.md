## ADR-006: Bezstanowe JWT (ES256) i DynamoDB Global Tables dla `/auth`

* **Status:** Zaakceptowany
* **Data:** 2026-11-22
* **Kontekst:** Ścieżka `/auth` obsługuje **4 355 Peak RPS** (w tym fale logowań po wydaniu aktualizacji gier) i musi utrzymać opóźnienie **p99 < 100 ms** oraz SLO **99,95%**.
* **Decyzja:** Autoryzację żądań API opieramy na krótkotrwałych tokenach **JWT (15 min)** podpisanych asymetrycznie algorytmem **ES256** (weryfikowanych lokalnie w pamięci kontenerów ECS w < 0,5 ms). Stan sesji i długotrwałe *Refresh Tokeny* (30 dni) przechowujemy w **Amazon DynamoDB Global Tables** (`eu-central-1` <-> `eu-west-1`) w trybie On-Demand z włączonym TTL.
* **Konsekwencje:**
* **Pozytywne:** Logowanie i autoryzacja są całkowicie niezależne od baz relacyjnych Aurora — nawet pełna niedostępność SQL nie odcina graczy od wejścia do gry; natywna replikacja *Active-Active* DynamoDB sprawia, że przełączenie DR nie wylogowuje użytkowników.
* **Negatywne:** Brak możliwości natychmiastowego unieważnienia pojedynczego *Access Tokena* przed upływem 15 minut (akceptowalne w grach; krytyczne blokady kont sprawdzamy przy odświeżaniu tokena i płatnościach).
