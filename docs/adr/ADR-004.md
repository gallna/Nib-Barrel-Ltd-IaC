## ADR-004: Amazon Aurora Global Database (I/O-Optimized) i RDS Proxy

* **Status:** Zaakceptowany
* **Data:** 2026-11-22
* **Kontekst:** Ekosystem wymaga 3 klastrów PostgreSQL (API #1–#3) oraz 1 klastra MySQL (API #4). W szczycie 273 kontenery Fargate mogą otworzyć tysiące połączeń jednocześnie, a replikacja między regionami musi utrzymać **RPO ≤ 5 min** przy dużym obciążeniu zapisu.
* **Decyzja:** Wdrażamy osobne klastry **Amazon Aurora Global Database** (instancje Graviton `db.r8g` w trybie **Aurora I/O-Optimized**) przedzielone warstwą **Amazon RDS Proxy** (osobne endpointy Read/Write i Read-Only).
* **Konsekwencje:**
* **Pozytywne:** Replikacja na poziomie pamięci masowej osiąga opóźnienie **< 1 sekundy** bez obciążania CPU instancji *Writer*; RDS Proxy chroni bazy przed wyczerpaniem puli połączeń i maskuje przełączenia lidera wewnątrz regionu w czasie **1–3 sekund**.
* **Negatywne:** Konieczność dostosowania zapytań SQL, aby nie używały zmiennych sesyjnych blokujących przypisanie połączenia (*pinning*) w RDS Proxy.
